# Cloudflare 费用风险审计

## 1. 给非程序员的摘要

有几处会让任务重复运行、每日额度被多用，自动助手也可能把暂停的服务重新打开。  
先把处理结果放到另一个文件夹，阻止同一份文件被反复处理。  
再修好每日总额度，确保两个请求同时来时不会多放行。  
收好账户密钥，让自动助手只能查询和暂停，恢复交给你确认。  
提醒是否送达、实际用量、暂停能否生效，还没有证据。

## 4. 付费路径清单

- 定时写文件→通知→处理结果：结果再次触发处理，重复通知也会增加读写。
- 生成报告→失败后再试：失败次数被清零，可能超过预定三次。
- 多个任务→共用每日额度：同时检查时可能多放行。
- 网页→查询进度：页面藏到后台后仍可能发请求。
- 告警→自动助手→暂停或恢复：密钥、权限、重复分析和处理报告有问题。
- 文件留存与套餐费用：计费范围、共享额度仍需核对。

## 5. 优先发现

### F-01 结果文件又被当成新文件处理，费用反复产生

**高｜第二层 代码限制**  
位置：`src/r2-consumer.js:4–40`。  
为什么花钱：结果仍放在被监听的文件夹，覆盖旧文件也会再触发处理；每日额度和暂停仍可限制后续工作。  
怎么修：把结果存到另一个文件夹，并让处理程序跳过结果文件。  
*规则：L2-08、L2-12；[官方说明](https://developers.cloudflare.com/r2/buckets/event-notifications/)。*

### F-02 两个请求同时进来，每日总额度可能被多用

**高｜第二层 代码限制**  
位置：`src/quota.js:3–14`。  
为什么花钱：两个请求可能读到同一个剩余额度，各自扣除后都开始干活，实际做的事比记下的多。  
怎么修：让所有请求从同一处扣额度，检查与扣除一次完成，再开始处理。  
*规则：L2-05、L2-07；[官方说明](https://developers.cloudflare.com/kv/concepts/how-kv-works/)。*

### F-03 账户密钥会被发给外部模型，权限也给得太多

**高｜第四层 Agent 接管**  
位置：`planned-agent/adapter.js:72–85`。  
为什么花钱：密钥进入外部模型，跨账户写权限还能删除服务。  
怎么修：由你的服务保管密钥，助手只准查询和暂停指定项目。  
*规则：L3-11、L4-03、L4-09；[权限说明](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/methods/delete/)。*

### F-04 自动助手可能把刚暂停的服务重新打开

**高｜第四层 Agent 接管**  
位置：`planned-agent/adapter.js:4–18,55–94`。  
为什么花钱：规则暂停后，助手仍可自行放行新任务；旧报告和队列不会因此自动重启。  
怎么修：移除自动助手的恢复工具，恢复必须由你批准。  
*规则：L3-10、L3-13、L4-02、L4-05、L4-06。*

### F-05 告警里夹带的话，可能让自动助手做错事

**高｜第四层 Agent 接管**  
位置：`planned-agent/adapter.js:72–91`。  
为什么花钱：告警混进给助手的指令，可能诱导它选择恢复等操作。  
怎么修：把告警作为资料单独传入，由你控制的服务限制能执行的动作。  
*规则：L4-04；[官方说明](https://developers.openai.com/api/docs/guides/agent-builder-safety)。*

### F-06 任务失败三次后，仍可能继续尝试

**中｜第二层 代码限制**  
位置：`src/export-job.js:48–81`。  
为什么花钱：重新安排运行时清零了失败次数；虽有间隔和暂停检查，次数上限仍失效。  
怎么修：累计保存失败次数，达到上限后结束，下次运行前不要清零。  
*规则：L2-08、L2-10。*

### F-07 同一条通知再送一次，文件就可能多处理一次

**中｜第二层 代码限制**  
位置：`src/r2-consumer.js:18–43`。  
为什么花钱：未记录哪个版本已处理；重复通知，或写完但未确认就中断，都可能再次读写。  
怎么修：记录每个文件版本的处理结果，重复通知先核对，避免盲目重做。  
*规则：L2-09、L2-11；[投递说明](https://developers.cloudflare.com/queues/reference/delivery-guarantees/)。*

### F-08 以为定时任务已经关闭，它却可能继续运行

**中｜第三层 自动暂停**  
位置：`ops/pause-runbook.md:25–31`。  
为什么花钱：删去定时设置，云端仍保留旧计划；暂停开关只挡住后续文件写入。  
怎么修：明确把定时计划设为空，发布后再查看云端列表确认。  
*规则：L3-06、L3-07；[官方说明](https://developers.cloudflare.com/workers/wrangler/configuration/#triggers)。*

### F-11 处理报告缺少关键数字，很难确认是否止住费用

**中｜第四层 Agent 接管**  
位置：`planned-agent/adapter.js:45–53,93–94`。  
为什么花钱：报告漏了统计时段、更新时间、用量对比和剩余任务，难以判断效果；它未宣称费用已停。  
怎么修：补齐数字、操作及之后的状态，写清已确认与待查证的事项。  
*规则：L4-08。*

### F-09 同一条告警反复送来，会重复花钱分析

**低｜第四层 Agent 接管**  
位置：`planned-agent/adapter.js:39–100`。  
为什么花钱：重复告警会再暂停、再调用模型；每天20次的模型上限不限制重复暂停请求。  
怎么修：记住告警的处理结果，重复送达时先核对，并限制重复请求。  
*规则：L4-07。*

### F-10 页面切到后台，还可能不断查询进度

**低｜第二层 代码限制**  
位置：`web/status.js:13–46`。  
为什么花钱：页面隐藏不暂停查询；完成、连续报错或关页会停，但后台仍可能增加请求和读取。  
怎么修：页面隐藏时停查，重新可见后恢复，久等没有变化时降低查询频率。  
*规则：L2-15。*
